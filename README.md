# switchVPNzapret

Автопереключатель `zapret` ↔ **Happ** (VPN) для Windows.

**Запустился `happ.exe` → zapret (winws.exe) молча закрывается** — чтобы Happ не ругался
«Conflicting Software Detected (zapret / winws.exe)».
**Закрыли Happ → zapret снова молча поднимается** через ваш конфиг `general (ALT12).bat`.
Никаких окон, никаких мелькающих/висящих консолей, никакого ручного вмешательства.

> **Что именно детектируется:** процесс **`happ.exe`** (а не сетевые адаптеры).
> Именно его видит Happ и из-за него показывает табличку конфликта.
>
> **Как поднимается zapret:** строго через `general (ALT12).bat` (в нём правильный конфиг
> `winws.exe`), но батник вызывается **невидимо** — окно `cmd` не появляется вообще,
> а сам процесс `winws.exe` остаётся виден в диспетчере задач и нормально работает.

## Файлы

| Файл | Что делает |
|---|---|
| `switchVPNzapret.ps1` | Основной скрипт. Слушает WMI-события старта/останова процесса `happ.exe` + страховочный таймер. |
| `switchVPNzapret.vbs` | Невидимый launcher. Запускает PowerShell без окна и ждёт его завершения, чтобы задача планировщика была `Running`, пока скрипт жив. |
| `install_autostart.bat` | Создаёт задачу планировщика `SwitchVPNZapret` (от SYSTEM, при старте ПК, скрыто). |
| `uninstall_autostart.bat` | Удаляет задачу планировщика. |

---

## Как это работает

1. При старте ПК планировщик стартует задачу `SwitchVPNZapret` — она через `switchVPNzapret.vbs` крутит `switchVPNzapret.ps1` в фоне от SYSTEM. Пока скрипт жив, задача в планировщике должна быть `Running` / «Выполняется».
2. Скрипт сразу приходит в консистентное состояние и дальше **ничего не делает**, пока ничего не меняется.
3. Как только **запускается процесс `happ.exe`** (WMI-событие `__InstanceCreationEvent`):
   - добивает `winws.exe` принудительно (`taskkill /T /F` + `.NET Kill()`, с повторами и проверкой);
   - если zapret вдруг установлен ещё и службой — останавливает её, чтобы не перезапускала winws.
   - → Happ больше не видит конфликт, табличка не появляется.
4. Как только **процесс `happ.exe` завершился** (WMI-событие `__InstanceDeletionEvent`):
   - **невидимо** запускает `general (ALT12).bat` (`cmd /c` с `CreateNoWindow` + `WindowStyle Hidden`);
   - батник отрабатывает (`start /min winws.exe` с нужным конфигом) и закрывается;
   - `winws.exe` остаётся работать и виден в диспетчере.
5. За сеанс можно включать/закрывать Happ сколько угодно раз — всё отрабатывает мгновенно по WMI-событию. Плюс есть страховочный таймер (раз в 10 сек), который перепроверяет состояние на случай пропущенных событий.

> `general (ALT12).bat` запускается с переменной окружения `NO_UPDATE_CHECK=1`,
> чтобы при автозапуске он не лез в интернет за проверкой обновлений.

Логи пишутся в `%ProgramData%\zapret-vpn-switch\vpn-zapret.log` (ротация 512 КБ).

## Что было исправлено (важно)

### Версия 3 — переход на детект процесса Happ и запуск через `general (ALT12).bat`

Суть задачи уточнилась: Happ ругается на конфликт именно из-за **процесса `winws.exe`**, а триггер —
запуск **`happ.exe`**. Плюс zapret должен подниматься **только** через свой конфиг `general (ALT12).bat`,
причём невидимо (без висящего окна `cmd`). Переделано:

- **Триггер теперь — процесс `happ.exe`, а не сетевые адаптеры.** Подписка на WMI
  `__InstanceCreationEvent`/`__InstanceDeletionEvent` для `Win32_Process` → мгновенная реакция
  на запуск/закрытие Happ. (Раньше ловили адаптеры `Up/Down`, что к табличке конфликта
  прямого отношения не имеет.)
- **Запуск zapret строго через `general (ALT12).bat`, невидимо.** `cmd /c "<bat>"` с
  `CreateNoWindow=true` + `WindowStyle=Hidden` → **окно cmd не появляется вообще**, батник
  отрабатывает `start /min winws.exe` и закрывается, а `winws.exe` остаётся виден и работает.
  Больше не нужна служба и не нужен прямой запуск winws.exe без конфига.
- Путь к батнику настраивается: параметр `-GeneralBat`, переменная `batPath` в `.vbs`,
  массив `$GeneralBatFallbacks` или автопоиск рядом со скриптом / в `C:\zapret\`.
- `NO_UPDATE_CHECK=1` при запуске батника — чтобы при автозапуске он не лез в сеть.
- Скрипт ждёт реального появления `winws.exe` (до 6 сек) и логирует результат.

### Версия 2 — надёжное убийство winws.exe

1. **`winws.exe` висел при остановке (главный баг).**
   Служба `zapret` запускает `winws.exe` через `binPath`, но сам `winws.exe` **не является корректной Windows-службой** и не реагирует на `SERVICE_CONTROL_STOP`. Поэтому `sc stop zapret` вешал службу в `STOP_PENDING`, а процесс оставался в памяти.
   → Теперь после `sc stop` процесс **принудительно добивается** через `taskkill /T /F` (вместе с деревом дочерних) + `.NET Kill()`, **с 5 повторами и контрольной проверкой**. Функция `Kill-Winws`.

2. **VPN-адаптер мог не детектиться** (актуально для старой логики адаптеров).
   `Get-NetAdapter` без `-IncludeHidden` не показывает скрытые TUN-адаптеры (Happ/wintun часто Hidden).
   → В v3 детект адаптеров **полностью заменён** на детект процесса `happ.exe` (см. выше) — надёжнее и напрямую связано с причиной конфликта.

3. **Гонка WMI-событие ↔ таймер.**
   Оба источника могли дёрнуть `Sync-State` одновременно → двойной `sc stop`/`sc start`.
   → Добавлена сериализация через `Interlocked` (одновременно работает только один проход).

4. **Переменные/функции были не видны в обработчиках событий.**
   Action-блоки `Register-CimIndicationEvent`/`Register-ObjectEvent` выполняются в отдельном scope, где `$script:`-переменные **недоступны** (на Windows PowerShell 5.1 — и функции тоже).
   → Ключевые функции и лок объявлены в **глобальной** области (`global:`).

5. **WMI-подписка могла не оформиться.**
   `PreviousInstance` в `__InstanceModificationEvent` для `MSFT_NetAdapter` поддерживается не везде и ломал запрос → оставался только таймер.
   → Запрос упрощён (ловим любую модификацию, решение принимает идемпотентная `Sync-State`) + **fallback** на `root/cimv2 Win32_NetworkAdapter`. Если WMI не поднялся — таймер ускоряется до 3 сек.

6. **`install_autostart.bat` создавал невалидный XML.**
   Порядок элементов внутри `<Settings>` **нарушал XSD-схему** Task Scheduler (`RestartOnFailure` в конце, `Priority` не на месте) → `schtasks /Create /XML` падал. Плюс декларация `encoding="UTF-16"` при реальном UTF-8 содержимом.
   → Порядок приведён к XSD, добавлен `<IdleSettings>`, кодировка исправлена на `UTF-8`.

## Установка и проверка для новичка (один раз)

### 0. Что изменено в текущей версии

Раньше могло казаться, что задача «запустилась и сразу закрылась»: `.vbs` запускал PowerShell и сам сразу завершался. Теперь `.vbs` **ждёт PowerShell до конца**, но всё равно делает это скрыто. Поэтому после установки в планировщике задача должна быть **Running / Выполняется**, пока работает фоновый скрипт.

Также исправлена внутренняя блокировка `Sync-State`: из-за некорректного `[ref]` PowerShell мог завершаться на старте. Теперь используется `SemaphoreSlim`.

### 1. Куда положить файлы

1. Создайте папку, например:
   ```text
   C:\Tools\switchVPNzapret\
   ```
2. Положите туда файлы:
   - `switchVPNzapret.ps1`
   - `switchVPNzapret.vbs`
   - `install_autostart.bat`
   - `uninstall_autostart.bat`

Важно: путь лучше делать **без кириллицы**, **без пробелов по возможности** и **не в OneDrive**.

### 2. Где должен лежать zapret

Сам `zapret` должен быть распакован, например, сюда:

```text
C:\zapret\
```

Внутри него должен быть файл:

```text
C:\zapret\general (ALT12).bat
```

Именно через этот bat-файл скрипт будет запускать `winws.exe`.

Если `general (ALT12).bat` лежит в другом месте, откройте `switchVPNzapret.vbs` обычным Блокнотом и в начале файла заполните строку:

```vbscript
batPath = "C:\ВАШ_ПУТЬ\general (ALT12).bat"
```

Если файл лежит в `C:\zapret\general (ALT12).bat`, оставьте:

```vbscript
batPath = ""
```

### 3. Ручная проверка ДО автозапуска

Это нужно, чтобы понять: скрипт вообще может найти zapret и не падает ли он.

1. Откройте меню Пуск.
2. Напишите `PowerShell`.
3. Нажмите **правой кнопкой** по Windows PowerShell.
4. Выберите **Запуск от имени администратора**.
5. Вставьте команду ниже и нажмите Enter:

```powershell
cd "C:\Tools\switchVPNzapret"
powershell -NoProfile -ExecutionPolicy Bypass -File .\switchVPNzapret.ps1 -TestOnce -GeneralBat "C:\zapret\general (ALT12).bat"
```

Если путь к папке другой — замените `C:\Tools\switchVPNzapret` и `C:\zapret\general (ALT12).bat` на свои.

Нормальный результат выглядит примерно так:

```text
TestOnce: Happ=False  winws=True  (подробности в C:\ProgramData\zapret-vpn-switch\vpn-zapret.log)
```

Что означают значения:

| Значение | Что значит |
|---|---|
| `Happ=False` | Happ сейчас закрыт. Это нормально, если VPN не запущен. |
| `Happ=True` | Happ сейчас открыт. |
| `winws=True` | zapret / `winws.exe` работает. |
| `winws=False` | `winws.exe` не работает. Если Happ закрыт — смотрите лог, возможно не найден `general (ALT12).bat`. |

### 4. Как проверить процессы вручную

Все команды ниже вставляйте в **PowerShell от имени администратора**.

#### Проверить, запущен ли Happ

```powershell
Get-Process happ -ErrorAction SilentlyContinue | Format-Table Id, ProcessName, Path
```

Если ничего не вывело — Happ закрыт или процесс называется иначе.

#### Проверить, запущен ли zapret / winws

```powershell
Get-Process winws -ErrorAction SilentlyContinue | Format-Table Id, ProcessName, Path
```

Если ничего не вывело — `winws.exe` сейчас не запущен.

#### Проверить, жив ли сам фоновый скрипт

```powershell
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
  Where-Object { $_.CommandLine -like '*switchVPNzapret.ps1*' } |
  Select-Object ProcessId, CommandLine
```

Если команда что-то вывела — `switchVPNzapret.ps1` работает как фоновый процесс.

#### Проверить `.vbs`-обёртку планировщика

После установки автозапуска теперь обычно должен быть ещё и `wscript.exe`, который ждёт PowerShell:

```powershell
Get-CimInstance Win32_Process -Filter "Name='wscript.exe'" |
  Where-Object { $_.CommandLine -like '*switchVPNzapret.vbs*' } |
  Select-Object ProcessId, CommandLine
```

Если `powershell.exe` со `switchVPNzapret.ps1` есть, а `wscript.exe` нет — скрипт всё равно может работать, но планировщик хуже контролирует его перезапуск. В этой версии `wscript.exe` должен оставаться.

#### Посмотреть лог

```powershell
Get-Content "C:\ProgramData\zapret-vpn-switch\vpn-zapret.log" -Tail 80
```

В логе должны быть строки вроде:

```text
=== switchVPNzapret запущен ... ===
Конфиг zapret: C:\zapret\general (ALT12).bat
Подписка на старт/останов процесса happ.exe оформлена.
Страховочный таймер запущен ...
```

### 5. Правильная установка в автозапуск через планировщик

Самый простой и правильный вариант:

1. Откройте папку:
   ```text
   C:\Tools\switchVPNzapret\
   ```
2. Нажмите **правой кнопкой** по файлу:
   ```text
   install_autostart.bat
   ```
3. Выберите:
   ```text
   Запуск от имени администратора
   ```
4. Дождитесь сообщения `[OK]`.
5. Перезагрузите компьютер или сразу проверьте задачу командами ниже.

Что делает установщик:

- создаёт задачу `SwitchVPNZapret`;
- запускает её **при старте Windows**, до входа пользователя;
- запускает от имени **SYSTEM**;
- запускает не `.ps1` напрямую, а `switchVPNzapret.vbs`;
- `.vbs` запускает PowerShell полностью скрыто, поэтому новых окон быть не должно;
- у задачи отключён лимит времени выполнения (`ExecutionTimeLimit = PT0S`), поэтому она может работать постоянно.

### 6. Проверка задачи планировщика

Откройте **PowerShell от имени администратора** и выполните:

```powershell
schtasks /Query /TN "SwitchVPNZapret" /V /FO LIST
```

Что смотреть:

| Поле | Нормально |
|---|---|
| `TaskName` / `Имя задачи` | `\SwitchVPNZapret` |
| `Status` / `Состояние` | `Running` / `Выполняется` после установки и запуска |
| `Task To Run` / `Выполняемая задача` | `wscript.exe "...\switchVPNzapret.vbs"` |
| `Run As User` / `Запуск от имени` | `SYSTEM` или `NT AUTHORITY\SYSTEM` |

Запустить задачу вручную:

```powershell
schtasks /Run /TN "SwitchVPNZapret"
```

Остановить задачу вручную:

```powershell
schtasks /End /TN "SwitchVPNZapret"
```

Удалить задачу вручную:

```powershell
schtasks /Delete /TN "SwitchVPNZapret" /F
```

### 7. Главный функциональный тест

1. Убедитесь, что Happ закрыт.
2. Проверьте `winws.exe`:
   ```powershell
   Get-Process winws -ErrorAction SilentlyContinue
   ```
   Когда Happ закрыт, `winws.exe` должен быть запущен.
3. Запустите Happ.
4. Через 1–3 секунды проверьте:
   ```powershell
   Get-Process winws -ErrorAction SilentlyContinue
   ```
   Теперь `winws.exe` должен пропасть.
5. Закройте Happ полностью.
6. Через 1–10 секунд снова проверьте:
   ```powershell
   Get-Process winws -ErrorAction SilentlyContinue
   ```
   `winws.exe` должен появиться обратно.

### 8. Удаление автозапуска

Самый простой вариант:

1. ПКМ по `uninstall_autostart.bat`.
2. **Запуск от имени администратора**.

Или вручную из PowerShell / CMD от администратора:

```powershell
schtasks /End /TN "SwitchVPNZapret"
schtasks /Delete /TN "SwitchVPNZapret" /F
```

## Почему именно так (а не Startup / реестр Run)

| Способ | Проблема |
|---|---|
| Папка `shell:startup` + `.ps1` | PowerShell мелькает окном, работает только после входа пользователя. |
| Реестр `HKCU\...\Run` → `powershell.exe -WindowStyle Hidden` | Окно всё равно мелькает на долю секунды. Только текущий пользователь. |
| **Task Scheduler, SYSTEM, BootTrigger, Hidden, через `.vbs`** | ✅ Запуск до входа. ✅ Окон нет вообще. ✅ Автоперезапуск при падении. ✅ Нет лимита по времени. |

VBS-обёртка с `WScript.Shell.Run(..., 0, True)` — надёжный способ запустить PowerShell без мерцания окна и при этом оставить задачу планировщика в состоянии `Running`, пока фоновый скрипт жив.

# Разбор `service.bat` от Flowseal/zapret-discord-youtube

Меню вызывается двойным кликом по `service.bat` (от админа).

## 1 / 2 / 3 — Install / Remove / Status Service

- **Install** — выбираете `general*.bat` → `winws.exe` ставится как служба `zapret` с нужными аргументами. Автозапуск Windows.
- **Remove** — удаляет службы `zapret` и `WinDivert` + убивает `winws.exe`.
- **Status** — какая стратегия сейчас, работает ли сервис, бежит ли `winws`.

## 4. Game Filter — что выбирать для Dota 2

Этот пункт включает/выключает дополнительные правила DPI для **игровых портов** в блоках `--filter-tcp=%GameFilterTCP%` и `--filter-udp=%GameFilterUDP%` в вашем `general*.bat` (последние две строки).

Варианты:
| Опция | Что делает | Для Dota 2 |
|---|---|---|
| 1. Disable | Игровые порты не трогаются вообще. | 👍 **Это и выбирай** в 99% случаев. |
| 2. TCP and UDP | DPI-обход применяется и к TCP, и к UDP игровых портов. | Может ломать матчмейкинг, пинг прыгает, реконнекты. |
| 3. TCP only | Обход на игровых TCP-портах. | Dota по TCP почти не ходит — бесполезно + потенциальный лаг. |
| 4. UDP only | Обход на игровых UDP-портах. | Dota ходит по UDP → **именно это чаще всего и ломает голосовой чат / повышает пинг**. |

### Короткий ответ для Dota 2 / CS2 / любого соревновательного онлайна
**Game Filter → `1. Disable`.** Низкий пинг и стабильный коннект важнее, чем «вдруг какая-то игра тоже заблокирована». Discord/YouTube обходятся отдельными блоками правил, Game Filter к ним отношения не имеет.

Включайте Game Filter **только если**:
- конкретная игра у вас не коннектится / матчмейкинг не ищет;
- вы готовы в п. 5–7 вручную сузить диапазон портов до портов именно этой игры (например, `27000-27050` для Steam), а не держать весь `1024-65535`.

Диапазон `1024-65535` на TCP+UDP — это по сути «обход для всего интернета, кроме системных портов». С этим Dota будет работать нестабильно.

## 5. IPSet Filter — loaded / any / none

Эта настройка переключает содержимое файла `lists/ipset-all.txt`, который подхватывается параметрами `--ipset="…\ipset-all.txt"` в последних блоках `general*.bat`. То есть **на какой диапазон IP вообще применяются эти «общие» правила обхода**.

| Режим | Что внутри `ipset-all.txt` | К кому применяется обход |
|---|---|---|
| **loaded** | Актуальный список IP-подсетей заблокированных сервисов из репозитория (Discord-голос, YouTube CDN, Spotify и т.д.). | Только к этим IP. Чисто, точечно, минимум побочек. |
| **none** | Одна строка `203.0.113.113/32` (документный IP, которого в природе не бывает). | Фактически **ни к кому** — правила-с-ipset выключены. |
| **any** | Пустой файл. | **Ко всем IP вообще** — zapret будет вмешиваться во всё TCP/UDP по заданным портам. |

### Что выбирать

- **loaded** — ✅ **стандартный и правильный выбор.** Хочется ещё меньше шанса словить баг → раз в пару недель жать «Update IPSet List» (пункт 8).
- **any** — только когда ваш провайдер блокирует что-то, чего нет в списке Flowseal, и вам ok, что zapret теперь лезет во весь трафик. Для игр **не рекомендую** — это ровно та комбинация, которая добавляет пинг и ломает голосовой чат.
- **none** — отключает ipset-блоки целиком. Остаются только блоки c `hostlist=...` (Discord, YouTube — ходят через `--hostlist=list-general.txt`). Полезно для диагностики: «проверить, не из-за ipset ли ломается игра».

### В одной фразе
**Для Dota 2 + Discord/YouTube: Game Filter = Disable, IPSet Filter = loaded.** Это даёт разблокировку Discord/YouTube и **не трогает** игровой трафик.

## 7. Replace active fakes — нужно ли проходить тесты

Это **не обязательная** штука, трогайте только если что-то не работает.

### Что это такое
В папке `bin/` лежит много `.bin`-файлов — это заготовки «фейковых» TLS/QUIC-пакетов, которыми zapret сбивает DPI провайдера. Два из них «активные» — на них ссылается `general.bat`:
- `ACTIVE_DISCORD_UDP.bin` — для голоса в Discord (`--dpi-desync-fake-discord=...`);
- `ACTIVE_GAME_UDP.bin` — для `--dpi-desync-fake-unknown-udp=...` в игровых блоках.

Меню «Replace active fakes» просто **копирует** любой выбранный `.bin` поверх `ACTIVE_*.bin`. То есть вы меняете «маскировку», которой прикидывается ваш трафик (под Google, под 4PDA, под Sferum и т.д.).

### Когда и как это использовать
1. **Если всё работает — не трогайте.** Дефолт настроен адекватно.
2. Если конкретно у вас **голос в Discord хрипит / отваливается**:
   - запустите пункт **12. Run Tests** — он прогонит разные `.bin` и покажет, какие стратегии работают именно у вашего провайдера;
   - потом сюда (пункт 7) и подставите тот фейк, который «зашёл» в тестах;
   - перезапустить сервис (`sc stop zapret` → `sc start zapret` или `Remove Services` → `Install Service`).
3. Для игрового UDP (`ACTIVE_GAME_UDP.bin`) замена нужна ещё реже — большинству помогает дефолт.

### Короткий ответ
**Тесты проходить не обязательно.** Пройдите только если симптомы (хрипит Discord, не грузит YouTube) не лечатся сменой стратегии (`general.bat` → `general (ALT*).bat`).

## 8 / 9 / 10 — Updates

- **Update IPSet List** — обновить `lists/ipset-all.txt` с GitHub.
- **Update Hosts File** — обновить системный `hosts` (нужно для некоторых сервисов).
- **Check for Updates** — проверить, вышла ли новая версия Flowseal/zapret.

## 11. Run Diagnostics — пробегитесь один раз

Проверит кучу всего (Base Filtering Engine, прокси, TCP timestamps, конфликтующие bypass-утилиты типа GoodbyeDPI, Adguard, Killer, CheckPoint, кириллицу в пути, OneDrive, VPN-сервисы, DNS, hosts). **Крайне рекомендую прогнать один раз** — закроет 90% будущих вопросов «почему не работает».

## 12. Run Tests

Прогоняет PowerShell-тестер (`utils/test zapret.ps1`), который проверяет работоспособность разных стратегий и фейков у **вашего** провайдера. Нужен только если дефолтные стратегии у вас плохо работают.
